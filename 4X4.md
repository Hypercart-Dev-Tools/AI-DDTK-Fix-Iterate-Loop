## 4. Recent Lessons Learned
**Capture insights to improve processes and avoid repeating mistakes.**

1. **Trinity spike — disjoint-files-per-event is the right primitive for multi-agent coordination over git.** One JSONL file per event under `.tick/events/` produced zero merge conflicts across all 7 acceptance tests. Agents only ever create new files, never edit shared ones; the projector folds them into `STATE.md` deterministically. ([experiments/coordination-layer/RECAP.md](experiments/coordination-layer/RECAP.md))
2. **Trinity spike — one-shot `tick claim` is a soft mutex, not a hard one.** An agent's first claim can return `won=true` and only learn it lost on the next re-project (when a peer's earlier-timestamped event lands). The deterministic tie-breaker handles correctness; agents must re-check before doing irreversible work. Phase 2 needs a `--confirm` second phase if strong-mutex semantics are required.
3. **Trinity spike — `git worktree` friction may kill multi-agent adoption.** `git worktree add` refuses to check out the same branch twice. The per-agent-child-branch workaround works but adds enough friction it could be the deciding factor between graduate and abandon. Worth solving before scaling beyond 2 agents.
4. The VS Code extension's real value is zero-config workspace onboarding (MCP server auto-discovery), not wrapping terminal commands with UI chrome.
